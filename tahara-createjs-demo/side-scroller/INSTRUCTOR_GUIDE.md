# 講師用ガイド：CreateJS横スクロールゲーム（約10時間）

## 1. 教材設計の方針

本教材は、次の二資料を踏まえて構成しています。

- `2026_募集要項.pdf`
- `2026_jsgame_schoolnote.pdf`

募集要項では、全国の高校1～3年生を対象とし、JavaScriptを使ってグループでオリジナルゲームを作るコースが示されています。コーステキストでは、CreateJS、HTML、JavaScriptの基礎、変数、条件分岐、配列、入力、当たり判定、画像・効果音、グループワークという順序で学ぶ構成です。

ただし、プログラミング未経験者へ約10時間で横スクロールゲームを完成させる場合、テキストの内容を広く順番に教えるより、次を優先します。

1. 開いた時点で遊べる
2. 最初の10分で見た目か動きが変わる
3. 生徒が触るファイルを2個に限定する
4. ゲーム本体を壊しにくくする
5. 目的→実行→仕組みの順に説明する
6. 一度に扱う概念を一つにする
7. 写経ではなく、数値・条件・結果を自分で選ばせる

## 2. ファイルの役割

| ファイル | 役割 | 授業での扱い |
|---|---|---|
| `settings.js` | 数値、色、ステージデータ | 1日目の中心 |
| `student.js` | 条件分岐と追加機能 | 2日目の中心 |
| `game.js` | 描画、物理、当たり判定、カメラ | 原則見せるだけ |
| `index.html` | Canvasと読み込み | HTMLの役割を説明するときのみ |

`game.js`を編集対象から外すことで、エラーによる全停止を減らし、生徒は「どこを変えるか」に集中できます。

休憩は別枠、またはクラスの状況に合わせて各区切りに入れてください。

## 4. 2日目最初の復習質問

講師が答えを説明する前に、生徒に画面やファイルを指さして答えてもらいます。

1. プレイヤーの速さを変えた場所はどこか
2. ジャンプを高くするには、どの数値をどう変えたか
3. 敵を追加するとき、何をコピーしたか
4. `x`を大きくすると、敵はどちらへ移動したか
5. `if`は、どのようなときに使うものか
6. 保存した後、ゲームへ反映するために何をしたか

答えが完全でなくても、実際のファイルを開いて一緒に探します。

## 5. 説明の順序

### 例：移動速度

1. **目的**：「キャラクターを速くしよう」
2. **実行**：`playerMoveSpeed: 5`を`8`へ変更
3. **仕組み**：「この数値をゲーム本体が毎回の移動量として使っている」

### 例：条件分岐

1. **目的**：「コインを全部取ったらクリアにしよう」
2. **実行**：取得枚数と全部の枚数を比べる
3. **仕組み**：`if`は条件が成立した場合だけ中の処理を行う

最初から「変数とは」「オブジェクトとは」と定義しません。変更の結果を見せた後に、必要な名称を付けます。

## 6. 小さな機能追加：共通ルール

一つの課題を次の3段階に分けます。

1. 必要な変数・データを作る
2. `if`で条件を判定する
3. 条件成立時の処理を書く

一度に完成コードを配布しません。各段階で保存・実行し、エラーがないことを確認します。

---

# 機能追加A：コインをすべて取るとクリア

使用箇所：`student.js`

## 段階1：数える変数

ファイル上部へ書きます。

```js
let myCoinCount = 0;
```

ここでは「変数は数を覚える箱」とだけ説明します。

## 段階2：取るたびに1増やし、条件を確認

`studentOnCoinCollected`の中へ、まず次を書きます。

```js
myCoinCount = myCoinCount + 1;
```

その後、条件の入口を書きます。

```js
if (myCoinCount === game.totalCoins) {
```

`===`は左右が同じかを調べる、と説明します。

## 段階3：成立したときの処理

`if`の中へ次を書き、最後に`}`で閉じます。

```js
game.clear("コインを全部集めた！");
```

発展：コインが残っている場合にメッセージを表示させます。

---

# 機能追加B：特定の場所でメッセージを表示

使用箇所：`settings.js` と `student.js`

## 段階1：エリアを作る

`messageZones`へ一行追加します。

```js
{ id: "secret", x: 1800, y: 300, width: 180, height: 160, text: "秘密の場所！" }
```

この段階では、x・y・width・heightで範囲を作ったことだけ確認します。

## 段階2：どのエリアかを判定

`studentOnEnterZone`へ書きます。

```js
if (zone.id === "secret") {
```

## 段階3：メッセージを出す

`if`の中へ書きます。

```js
game.showMessage(zone.text);
```

発展：別のidのエリアを増やし、異なるメッセージを表示します。

---

# 機能追加C：敵を倒したときの得点を変える

使用箇所：`settings.js` と `student.js`

## 段階1：速い敵を一体作る

敵の一行をコピーし、例えば次のようにします。

```js
{ id: "fastEnemy", x: 3400, y: 420, speed: 4, range: 150 },
```

## 段階2：速い敵かを判定

`studentOnEnemyDefeated`へ書きます。

```js
if (enemy.id === "fastEnemy") {
```

## 段階3：追加得点

```js
game.addScore(500);
game.showMessage("速い敵ボーナス！");
```

発展：`enemy.speed >= 3`という条件に変更し、速さで得点を決めます。

---

# 機能追加D：アイテムで移動速度上昇

使用箇所：`settings.js` と `student.js`

## 段階1：アイテムを置く

`items`へ追加します。

```js
{ id: "speedItem", type: "speed", x: 2550, y: 250 }
```

## 段階2：アイテムの種類を判定

`studentOnItemCollected`へ書きます。

```js
if (item.type === "speed") {
```

## 段階3：5秒間速くする

```js
game.boostSpeed(1.7, 5);
```

発展：倍率と時間を自分で調整し、取りにくい位置へ置きます。

---

# 機能追加E：ボタンで扉を開く

使用箇所：`settings.js` と `student.js`

## 段階1：ボタンと扉を置く

`buttons`へ追加します。

```js
{ id: "button1", x: 3350, y: 440, width: 46, height: 20, doorId: "door1" }
```

`doors`へ追加します。

```js
{ id: "door1", x: 3750, y: 320, width: 50, height: 140 }
```

## 段階2：対象のボタンを判定

`studentOnButtonPressed`へ書きます。

```js
if (button.id === "button1") {
```

## 段階3：扉を開く

```js
game.openDoor(button.doorId);
```

発展：ボタンと扉を二組に増やします。

## 7. 完成コードを写させるだけにしない方法

- 数値は生徒自身に決めさせる
- 実行前に「どう変わると思うか」を答えさせる
- 変更後に「予想どおりか」を確認させる
- コピーした行のうち、最低2か所を自分で変更させる
- 機能を追加した理由を企画シートへ書かせる
- 友達へ変更場所を説明させる
- エラーが出たとき、すぐ答えを言わず、最後に触った行から確認させる

## 8. 複数人制作の進め方

推奨する役割は次のとおりです。

- ステージ担当
- プレイヤー・敵担当
- 画像・色・音担当
- テスト担当

ただし、完全分業にはしません。30～45分ごとに一度、各担当が次を他のメンバーへ説明します。

- どのファイルを変更したか
- どの数値・条件を変更したか
- なぜその変更をしたか
- 現在困っていること

## 9. 講師が止めるべき状況

- 一度に5か所以上変更し始めた
- 動作確認をせず長時間書き続けている
- `game.js`を大きく変更しようとしている
- 担当者一人だけが操作し続けている
- クリアできない状態のまま見た目だけを作り込んでいる

その場合は、最後に動いていた状態へ戻し、「一か所変更→保存→確認」の流れへ戻します。

## 10. 発表の型

1チーム2～3分を目安にします。

1. タイトルとゲームの目標
2. 選んだテーマ
3. 数値・配置で工夫したこと
4. `if`を使って追加した機能
5. テストで見つけ、直したこと
6. 実演

評価はコード量ではなく、変更の理由、遊べる状態、説明できることを重視します。

## 11. 授業前チェックリスト

- 全PCで`index.html`が開く
- 公式CreateJSまたは簡易互換版で描画される
- VS Codeで`settings.js`を保存できる
- `playerMoveSpeed`変更後に再読み込みで反映される
- キーボード操作がブラウザへ届く
- 音量とブラウザの自動再生制限を確認する
- 元の教材フォルダを別名で保管する
- 生徒ごと、またはチームごとにフォルダをコピーする
